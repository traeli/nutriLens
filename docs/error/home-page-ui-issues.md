## 详细问题

### HOME-UI-001：顶部未正确避开系统安全区

**现象**

- 系统时间与“食迹簿”重叠。
- 灵动岛遮挡城市名称和切换入口。
- 头像靠近或进入系统状态区域。
- 微信右上角原生胶囊覆盖城市图片。

**原因判断**

顶部布局只依赖 CSS 的 `env(safe-area-inset-top)`，没有结合小程序运行时的状态栏高度和微信胶囊位置进行计算。

**修复要求**

- 使用 `uni.getWindowInfo()` 获取状态栏及窗口信息。
- 使用 `uni.getMenuButtonBoundingClientRect()` 获取微信胶囊的位置与尺寸。
- 动态计算顶部导航高度、内容起点和右侧安全空间。
- 品牌、城市入口和头像均不得进入状态栏、灵动岛或微信胶囊区域。

**验收标准**

- 在刘海屏、灵动岛设备和普通直屏设备上均无重叠。
- 顶部元素垂直居中，城市入口和头像可以正常点击。

### HOME-UI-002：底部导航图标未显示

**现象**

“发现”“足迹”“我的”只有文字，没有对应图标；仅“记录”的加号正常显示。

**原因判断**

自定义 TabBar 内的图片资源可能存在路径解析、资源引用或组件加载问题，需要在微信开发者工具中确认资源请求和编译产物。

**修复要求**

- 确认四组导航资源均包含在小程序构建产物中。
- 确认自定义 TabBar 中的图片路径可以由微信原生组件正确解析。
- 为图片加载失败提供不会破坏布局的降级方案。

**验收标准**

- 四个栏目图标全部清晰显示。
- 图标中心位于同一水平线，文字位于同一基线。
- 图标加载前后不得引起导航抖动。

### HOME-UI-003：底部导航选中状态错误

**现象**

当前页面是“发现”，但“发现”显示为灰色，“记录”和“足迹”同时显示为红色。

**原因判断**

- “记录”文字被样式固定为红色。
- 自定义 TabBar 的当前路由状态没有在页面显示时可靠同步。

**修复要求**

- 当前路由必须与唯一的选中栏目对应。
- “记录”可以保留朱红色加号，但文字颜色需要遵循明确且唯一的状态规则。
- 从页面按钮、分享入口或程序化 `switchTab` 进入时也必须同步状态。

**验收标准**

- 首页只将“发现”标记为选中。
- 切换到其他 Tab 后只有目标栏目处于选中状态。
- 快速连续切换时不出现状态残留。

### HOME-UI-004：城市路线停在任意横向位置

**现象**

路线区域同时显示上一张地图残片、当前路线文字和下一张地图残片，无法判断内容归属。

**原因判断**

路线使用普通横向 `scroll-view`，缺少分页吸附和稳定初始位置。

**修复要求**

- 优先改用 `swiper`，或者实现明确的横向吸附逻辑。
- 默认完整显示第一张路线。
- 每次滑动结束后必须停在完整路线卡片的位置。
- 下一张路线只露出少量、可识别的预览区域。

**验收标准**

- 不操作时始终有一张路线完整可读。
- 不会停在两张路线的中间位置。
- 页面返回或城市切换后滚动位置符合产品预期。

### HOME-UI-005：城市图片相邻页露出异常

**现象**

城市大图左右出现很窄的相邻图片竖条，看起来像容器没有铺满。

**原因判断**

`previous-margin`、`next-margin`、外层负边距、卡片内边距和缩放效果叠加，导致相邻城市只露出不可识别的碎片。

**修复要求**

- 统一使用一种相邻页预览方案。
- 相邻城市需要有明确卡片间距和足够的可识别露出宽度。
- 不应同时叠加负边距和多层缩放补偿。

**验收标准**

- 默认状态看起来是有意设计的轮播，而不是图片裁切错误。
- 滑动过程中圆角、间距和缩放连续稳定。

### HOME-UI-006：顶部导航信息层级失效

**现象**

品牌、城市名称和头像受到系统区域遮挡，页面缺少稳定可用的导航头部。

**修复要求**

- 顶部品牌、城市入口、头像和微信胶囊形成清晰、互不重叠的布局。
- 城市名称不得被灵动岛或胶囊截断。
- 头像需要保留符合微信小程序规范的点击区域。

### HOME-UI-007：页面内容整体过度压缩

**现象**

搜索框、记录控制器、路线内容、最近记录和 Banner 都比参考设计更紧凑，实际设备上文字与点击区域偏小。

**修复要求**

- 重新校准真实设备上的字号、行高、模块间距和触控面积。
- 主要点击区域建议不小于 `88rpx × 88rpx`。
- 辅助文字在常见微信小程序设备宽度下必须清晰可读。

### HOME-UI-008：路线模块信息可读性不足

**现象**

- 站点名称和地图标注过小。
- 路线编号过强，压制路线标题。
- 标题、元信息、线路和站点被压缩在过小高度内。

**修复要求**

- 降低路线编号的视觉权重。
- 增加路线标题和站点的有效宽度。
- 提高站点、时间和距离信息的最小字号。
- 地图预览与文字信息必须保持明确从属关系。

### HOME-UI-009：记录控制器内部比例失衡

**现象**

- “记录这一餐”区域过宽。
- 拍照、语音、文字入口过窄。
- 分割线数量较多，控件显得拥挤。
- 语音图标像普通圆点，语义不清。

**修复要求**

- 重新分配主操作与三个快捷入口的宽度。
- 统一图标尺寸、线条粗细和文字间距。
- 使用可明确识别的相机、麦克风和文字图标。

### HOME-UI-010：征集 Banner 信息过小

**现象**

栏目名、主标题和描述文字整体偏小，右侧图片与箭头挤压文字空间。

**修复要求**

- 保证主标题是一眼可读的主要信息。
- 调整图片占比和箭头位置，避免侵占文案区域。
- Banner 保持编辑栏目感，不能退化为普通广告条。

### HOME-UI-011：非上海城市使用餐饮图片占位

**现象**

苏州等城市显示的是餐厅、面条或咖啡店图片，不具备对应城市的视觉识别度。

**修复要求**

- 为上海、杭州、苏州和南京分别提供正式城市图片。
- 图片映射继续使用城市代码，不改变现有滑动切换逻辑。
- 正式图片应统一比例、画面质量和文字安全区域。

### HOME-UI-012：上海城市图包含烘焙 UI

**现象**

上海图片由设计稿截图裁剪得到，图片内部已经包含城市名称、描述、定位状态、切换城市文案和圆角边缘。

**影响**

- 图片中的文字无法响应点击。
- 文字无法根据屏幕宽度和系统字体调整。
- 上海与其他城市的文字清晰度、位置和样式不一致。

**修复要求**

- 替换为不包含任何 UI 元素的上海原始城市图片。
- 城市名称、描述、定位状态和切换入口全部由页面代码绘制。

## 建议修复顺序

1. 修复顶部系统安全区和微信胶囊避让。
2. 修复底部导航图标加载和唯一选中状态。
3. 修复城市路线分页吸附和内容完整性。
4. 修复城市轮播的相邻页露出方式。
5. 调整实际设备上的字号、间距和模块高度。
6. 替换各城市正式图片资源。
7. 最后细化记录控制器和征集 Banner。

## 整体验收范围

- 至少检查一台灵动岛设备、一台刘海屏设备和一台普通直屏设备。
- 验证首页首次进入、城市滑动切换、ActionSheet 切换城市、Tab 切换和页面返回。
- 验证四个底部导航栏目等宽、等距、图标中心对齐、文字基线对齐。
- 微信开发者工具无资源 404、组件错误和明显样式警告。
- 页面与参考设计保持一致，同时确保所有文字和操作由真实组件承载。
